## 0. 修订结论与决策摘要

本稿保留“图片输入→是/否/不确定及简短理由”的目标，重构执行与运维架构。原稿中的外部实验数据作为容量规划的初始输入，需在目标负载下重新标定。

核心决策：

1. 批量任务采用持久化队列与异步结果查询，单图交互复用同一任务执行链路。
2. 生产后端优先选择满足能力要求的正式 API 或自部署模型，通过统一适配接口接入。
3. Web 网关后端与官方 API 后端均为生产候选，通过统一适配接口接入，各自补齐能力差异表与实测数据后再定主次。网关侧资源池的容量由其自身限流决定，本服务只约束外层预算。
4. 统一调度入口负责预算、截止时间与重试，适配器内部不得再叠加不可见重试。
5. 凭证健康、网络健康、上游健康分别建模；失效资源自动停止接收新任务，人工负责诊断与确认恢复。
6. 扩容依据业务负载、有效完成率、排队时间和故障演练结果，不依据账号数量或单日存活比例。

## 1. 目标与边界

输入为通常 1–5 MB 的图片和版本化提示模板，输出为三分类结果：是、否、不确定，以及简短理由。请求之间无多轮会话依赖。

“不确定”是有效的业务判定结果；网络失败、超时、格式错误、图片未被接收均是技术失败，不得映射成“不确定”。

模型准确率另行验收。本方案必须提供模型版本、模板版本、预处理版本及有效图片输入的记录，使执行结果可定位和可复现；不将提示语本身视为结构化输出保障。

## 2. 服务目标与验收口径

以下为候选验收目标，不是已经达到的指标。

| 指标 | 候选目标与统计口径 |
|---|---|
| 在线单图延迟 | 在约定负载内，接入到有效结果的 P95 ≤30秒，包含排队、上传与重试；失败请求单独统计，不能移出报表 |
| 批量完成时限 | 由 B、W 确定，按整批全部任务进入终态计算 |
| 有效完成率 | 候选 ≥99%，分母为已接受且未由用户取消的有效任务；技术失败进入分母 |
| 无人值守 | 至少连续12小时，不依赖人工恢复才能维持正常调度 |
| 资源故障隔离 | 明确认证失效后立即停止新分配；事件触发为主，轮询补偿发现目标≤60秒 |
| 已接受任务持久性 | 只有任务元数据与输入引用持久化成功后才确认接收；具体跨故障域 RPO 待部署方案确认 |
| 恢复时间 | 候选 RTO≤30分钟，须通过恢复演练验证 |

明确排除非法文件、超过接口限制的输入等接入前拒绝；对过载请求在接受前拒绝，并单独报告拒绝率，避免通过拒绝请求掩盖容量不足。

## 3. 技术选型

### 3.1 后端候选

| 类型 | 定位 | 准入条件 |
|---|---|---|
| 正式图片理解 API | 首选生产候选 | 支持图片输入；配额、超时和错误语义可验证；能力验收通过 |
| 自部署图片判定模型 | 可选独立后端或预筛层 | 达到另行定义的质量门槛；具备性能、资源与版本管理数据 |
| Web 网关适配组件 | 生产候选 | 固定版本；容量由网关侧限流决定；网关故障时本服务按 `connection_failed` 重试并隔离 |

Gemini 官方提供图片理解 API，因此“没有任何官方程序化接口”不能作为选型前提。若所需 Web 能力与 API 不等价，应提交能力差异表与实测结果，再决定后端。

正式 API 文档：https://ai.google.dev/gemini-api/docs/image-understanding

### 3.2 统一适配接口

逻辑接口为 `analyze(task, input_ref, deadline) -> result`，还应支持能力查询与尽力取消。

返回数据包括标准化结果、实际后端/模型版本、上游请求标识、耗时、计费或配额消耗信息、标准化错误类型。后端不能提供的字段标记为未知，不构造估计值冒充实测。

能力声明包含输入尺寸、支持格式、并发限制、结构化输出、幂等与取消支持情况。切换后端必须通过同一组契约测试与独立质量验收。

## 4. 总体架构

```text
客户端 / 批量提交工具
        │
        ▼
接入层：鉴权、文件验证、幂等、容量准入
        │
        ├── 输入对象存储（明确有效期与清理规则）
        └── 任务数据库 + 事务 Outbox
                         │
                         ▼
                  持久化消息队列
                         │
                         ▼
             调度器：预算、优先级、截止时间
                         │
                         ▼
                    工作进程池
                         │
                 统一后端适配接口
                   ┌─────┴─────┐
                   ▼           ▼
              正式 API      自部署模型
                         │
                         ▼
             结果存储、批次汇总、状态查询

监控与健康控制器：观察各层状态并执行隔离
```

初期可以将接入、调度和工作进程部署在同一台机器，但保留逻辑边界。单机形态必须明确接受的故障恢复限制；需要主机故障下持续服务时再部署多故障域副本和存储高可用。

### 4.1 提交与恢复

1. 验证输入，保存对象并确认可读取。
2. 在同一数据库事务中写入任务与 Outbox 事件，成功后返回任务 ID。
3. 发布器将事件投递到队列；重复投递通过任务 ID 和状态版本消除重复领取。
4. 工作进程获取有期限租约，执行时维护心跳；完成结果以条件更新提交。
5. 工作者崩溃后，租约到期的任务重新进入恢复流程；已完成任务不能被旧工作者覆盖。
6. 数据库提交失败留下的孤立输入对象由定期清理任务回收。

队列按“至少一次投递”设计。任务去重只能避免本系统重复提交结果；若上游不支持幂等，无法承诺上游恰好执行一次。

## 5. 任务与结果模型

任务状态：`queued → running → succeeded / failed / cancelled / expired`；可重试错误通过单独的 attempt 记录返回排队状态。

每个任务至少记录：任务与批次 ID、幂等键、输入哈希及对象引用、创建时间、截止时间、状态版本、租约持有者、尝试次数、后端与版本、最终结果、错误分类。

每次上游尝试独立记录开始/结束时间、请求 ID、消耗、错误及“结果是否未知”。已经发出但响应丢失的请求不得直接认定为未执行。

结果采用受校验的数据结构，例如 `verdict ∈ {yes, no, uncertain}`、长度受限的 `reason` 和版本信息。仅在返回格式合法、图片请求完成且必需字段齐全时标记成功。

短输出任务默认返回完整结果，不要求流式输出；进度通过任务状态查询提供。

## 6. 调度与重试

### 6.1 预算与公平性

调度维度由正式后端实际配额确定，可包括项目、模型、区域及凭证。存在共享上级配额时，子资源限额总和不能绕过上级预算。

同时限制：在途并发、短窗口速率、长窗口总量、排队容量。实现可采用平滑发放配合严格窗口计数；如果采用令牌桶，必须明确桶容量，不能默认允许满桶瞬时突发。

先检查状态、预算、截止时间，再对合格资源进行公平分配。失败重试不能无限插队，大批次不能占满全部执行槽。

### 6.2 参数来源

| 参数 | 设置依据 |
|---|---|
| 并发 C | 上游允许并发与实测在途耗时；依据 λ×E[T] 估算，并验证长尾 |
| 每分钟/小时预算 | 后端确认的配额及内部成本预算；同时生效 |
| 队列上限 | 可在任务期限内完成的工作量，而非无限缓冲 |
| 单次超时 | 连接、上传、响应分别设限，受总截止时间约束 |
| 尝试次数 | 初期仅对明确可重试故障允许一次额外尝试；压测后调整 |
| 退避 | 尊重服务端等待指示，否则有界指数退避加抖动；等待不得越过任务期限 |

不沿用原稿“并发2–3、RPM10、RPH60”作为生产默认值。这些值缺乏目标负载和后端配额依据。

### 6.3 错误分类

| 错误 | 处理 |
|---|---|
| 本地预算不足 | 保留在有界队列；无法满足期限时接入前拒绝或任务到期 |
| 上游限流 | 遵守等待指示，降低该预算域发送速率；不扩散成全局重试 |
| 瞬时网络故障/可恢复服务错误 | 受截止时间和尝试预算约束重试 |
| 已发出、执行结果未知 | 优先查询上游状态；无查询/幂等能力时记录重复执行风险，按显式策略处理 |
| 明确认证失效 | 隔离凭证、停止新分配、告警 |
| 权限不足/需要验证 | 暂停相关任务和资源，等待确认；不透明迁移继续请求 |
| 输入非法 | 不重试，返回可解释错误 |
| 输出格式不合法 | 标记技术失败；只有预先验证的修复流程才允许额外调用 |

## 7. 资源池与健康控制

资源分为凭证、网络通道、后端服务三个对象，避免将所有错误累积到凭证失败次数。

凭证状态：`ready / paused / invalid`。认证失效进入 invalid；诊断中的资源进入 paused；恢复必须经过适合该能力的验证，不能只检查文本请求返回200。

网络和服务故障采用 `closed / open / half_open` 熔断状态；到达冷却时间只允许有限恢复检查，不直接恢复满负载。认证失效不依靠时间自动恢复。

外部健康控制器可通过稳定管理 API 实现隔离，准入条件包括：状态查询、幂等禁用、禁用后立即停止新分配、明确的版本兼容策略。若组件不满足，使用外部准入控制或修改适配器；不直接修改正在运行的组件数据库。

控制器需维护自身心跳，告警管理接口故障。采用事件触发和轮询补偿；故障域内大量同时失败时先判断共享依赖，避免误将全部凭证永久淘汰。

网络出口按连接稳定性、带宽和故障域管理。稳定绑定仅作为网络工程选择；多个资源共用通道时共享网络容量。同供应商或同路径的出口不能视为独立容灾。

## 8. 容量模型

设每日运行 H 小时、单预算域每分钟允许 Rm 次、每小时允许 Rh 次、并发 C、平均占用时间 T 秒，则忽略窗口边界瞬时效应的名义尝试容量为：

`U = min(60×H×Rm, H×Rh, 3600×H×C/T, 其他共享配额上限)`。

原参数全天运行时：`min(14,400, 1,440, 并发处理能力)`，所以小时限额约束下名义上限为1,440次尝试/日。并非1,440个成功任务。

有效任务容量可估算为 `U × A × p / a`，其中 A 为可服务时间或容量占比，p 为进入执行任务的最终有效完成率，a 为每个进入执行任务的平均上游尝试次数。三者必须采用相同观测期间与口径，避免重复扣减同一故障。

凭证存活比例不能直接替代 A。若仍使用每凭证每日最多5次的内部限制，50个凭证合计只有250次/日的名义预算，此时无需以出口速率推算更高容量。

缓存命中与预筛分流另行计入业务需求到上游需求的转换：`D_upstream = D × (1-h) × r`。排队与峰值能力需独立验证，日总量达标不代表峰值延迟达标。

单图大小为 s MB 时，仅一次上传的日数据量约为 `D_upstream × a × s` MB；还需计算下载、复制、编码、重试与日志。工作进程内存限制依据最大在途图片和实际解码峰值测量，不以压缩文件大小替代内存大小。

## 9. 预筛、去重与缓存

第一阶段实施精确哈希去重、版本化结果缓存、相同在途任务合并。缓存键包含输入内容与模型、模板、预处理版本；仅复用有效结果，失败不能成为长期缓存。

第二阶段按质量验收结果引入低成本预筛模型。元数据、尺寸或压缩特征不能独立证明图片真实性；近似图片去重不能直接复用结论，除非已经验证其适用边界。

预筛必须支持旁路、版本记录与抽样复核，监控分流比例变化。没有通过质量验收的预筛只能做实验，不改变生产结果。

## 10. 单点、持久化与多实例

| 依赖 | 防护与验证 |
|---|---|
| 接入和工作进程 | 可重启、无本地唯一任务状态；通过进程退出与主机故障演练验证 |
| 队列 | 持久化、重复投递安全、故障恢复；监控积压和最老任务年龄 |
| 数据库 | 备份、恢复演练、容量与连接池限制；生产高可用按RPO/RTO选型 |
| 输入对象存储 | 输入有效期覆盖重试与恢复窗口；访问失败可定位 |
| 单一后端 | 独立后端通过双重验收后启用，否则暂停接收并保留已接受任务 |
| 开源适配组件 | 固定版本、可复现构建、契约测试、维护负责人和回滚产物 |

换用共享数据库不等于实现多实例协调。多实例必须具备全局预算原子扣减、任务租约、条件提交、凭证刷新互斥和调度状态同步。租约过期后使用版本条件防止旧工作者覆盖新结果。

若协调存储不可用，不允许各实例自行恢复完整额度继续发送。

## 11. 可观测性与部署要求

任务级指标：接入、拒绝、排队、完成、失败、取消、到期数量，P50/P95/P99延迟，批次完成时间。

执行级指标：尝试次数、重试放大倍数、执行结果未知数、有效输出比例、配额消耗、单次有效结果成本。

依赖级指标：认证故障、限流、网络故障、后端服务错误、熔断状态、资源隔离时间、控制器心跳。

部署必须固定镜像摘要或二进制版本，不使用浮动latest作为发布依据。管理面与业务面分离，限制管理访问；秘密配置与日志隔离，禁止在日志中输出凭证。

远程图片获取限制目标地址、重定向、总字节数与时间，防止访问内部服务；解码设置像素、内存和CPU预算。数据库连接数、文件描述符、连接池及临时磁盘设置明确上限。

## 12. 验证与扩容门槛

### 阶段A：功能和故障验证

使用真实尺寸分布的图片验证输入、结构化结果、幂等、重复消息、进程重启、凭证失效、超时、限流、数据库短暂不可用及结果未知场景。不得以纯文本测试代替图片链路验收。

### 阶段B：代表性负载

按D、λ_peak、B、W构造持续与峰值负载，先在模拟后端测量调度器上限，再在后端确认配额内验证完整链路。完成至少12小时无人值守验证和覆盖日配额周期的观测；成本与生命周期估计需要更长窗口时继续观察，不按固定第14日强行定论。

### 阶段C：逐步扩容

一次只改变一个主要容量因素，每次扩容均需满足：

1. 既定成功率、在线延迟和批量完成时限达标。
2. 在设计峰值下无持续增长的任务积压。
3. 已完成约定故障演练，任务与结果可恢复。
4. 共享预算、存储、网络及后端容量仍有经测量确认的余量。
5. 单次有效结果成本不超过预算，重试和人工介入未异常增加。

任何条件失效则停止扩容并定位瓶颈。资源数量不再作为唯一阶段名称；扩工作进程仅解决本地计算瓶颈，提高后端容量需要已确认的配额或独立后端能力。

## 13. 成本与发布准入

`单图成本 = 预筛成本 + (1-h)×r×a×每次上游尝试成本 + 存储/网络/运维分摊`。

另记录每个有效结果的实际总成本，包含失败任务支出、计算资源、后端用量、维护与值守。对价格、调用分流比例、失败率分别进行敏感性测算，不以凭证消耗作为唯一成本指标。

发布前必须交付：业务规模表、后端能力与配额表、契约测试结果、代表性负载报告、故障恢复报告、监控告警配置、版本与回滚记录。尚未交付的项目明确标注负责人和时间，不标记为已完成。

## 14. Q1–Q6 修订后的回答

### Q1 调度参数

原参数缺乏生产依据，RPM10与RPH60对应不同时间尺度；长期受RPH约束。采用实际后端配额、平滑发送、有界队列、统一重试预算和总截止时间，经过代表性图片负载验证后确定数值。

### Q2 出口绑定

稳定绑定可用于连接管理与故障诊断，不视为可用性保证。共享出口共享网络容量和故障域；网络故障与上游访问拒绝分别处理。扩容以真实后端预算和网络测量为依据。

### Q3 自动摘除

只有在管理接口提供稳定、幂等、即时生效的禁用能力时，外部控制器才可实现可靠摘除。否则增加外部准入层或修改适配器。事件触发为主、轮询补偿，认证失效不自动按时间恢复。

### Q4 单点依赖

保留统一适配接口、固定版本和接管能力；同一上游的其他客户端不是独立容灾。独立后端必须通过能力和性能验收，否则明确积压、到期和暂停接入行为。

### Q5 吞吐

原配置全天运行的名义调度容量为1,440次尝试/预算域/日；成功任务量还受日额度、故障、重试及有效完成率限制。凭证可用比例不能直接等价为吞吐折扣。补齐业务量后才可判断是否满足需求。

### Q6 成本优化

先进行精确去重、结果缓存、在途请求合并，再引入通过独立质量验收的预筛。以每个有效结果的总成本与服务目标共同判断收益。
